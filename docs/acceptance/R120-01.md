# R120-01 Acceptance Scenarios

These executable scenarios cover user-visible search-language settings and the production matching pipeline.
All XCUITest launches use the explicit Debug acceptance mode and a unique temporary root. Matching scenarios use
the real `TMDbClient`, the production `MovieFolderProcessor`, and disposable persistence/folder fixtures.

## Scenario specifications

### R120-A1 — Global language survives relaunch

**Given** the app is launched with isolated acceptance storage and its global matching defaults are open,
**When** the user selects `pt-BR` and relaunches the app,
**Then** the Matching Defaults pane still displays `pt-BR`, and the settings record exists under the test root.

- Requirement: explicit persisted global search language.
- Automated test: `testGlobalSearchLanguagePersistsAcrossRelaunch` in `MovieFolderPostersUITests.swift`.
- Surface: full host-app XCUITest.

### R120-A2 — Collection inherits defaults and preserves an override

**Given** global search language is `pt-BR` and the user starts adding a collection,
**When** the collection uses application matching settings,
**Then** its language picker displays `pt-BR` and is disabled; after the user disables inheritance, selects `de-DE`,
saves, opens Edit Collection, and relaunches,
**Then** the saved override remains `de-DE`.

- Requirement: collection-level language configuration and inheritance.
- Automated test: `testCollectionLanguageInheritanceAndOverridePersist` in `MovieFolderPostersUITests.swift`.
- Surface: full host-app XCUITest with a test-created folder selected through the native open panel.

### R120-A3 — Choose Movie discloses and uses the effective language

**Given** an isolated collection contains a folder marked for manual matching and its effective language is `pt-BR`,
**When** the user opens Choose Movie,
**Then** the disclosure names `pt-BR` and no search request occurs until Search is explicitly pressed;
**When** the user presses Search,
**Then** the provider request carries `pt-BR` and the resulting candidates appear in the action window.

- Requirement: manual search uses the effective collection language and remains explicit.
- Automated tests: `testChooseMovieUsesSavedLanguageAndSearchesDeterministicFixture` in
  `MovieFolderPostersUITests.swift` and `movieSelectionSearchUsesSavedLanguage` in
  `MoviePosterActionServiceTests.swift`.
- Surface: full host-app XCUITest uses an isolated real settings/outcome store and a deterministic Debug transport;
  the action-service regression observes the language passed at the metadata-provider boundary.

### R120-A4 — Verified international alias preserves provider identity

**Given** the real TMDb client receives a complete search result and a provider alternative-title response whose ID
matches the candidate,
**When** the processor assesses a folder named with that verified Brazilian title and year,
**Then** the authoritative saved outcome retains that candidate ID and records the effective `pt-BR` search request.

- Requirement: provider-verified international/alternative-title provenance.
- Automated test: `verifiedInternationalAliasPersistsProviderMovieIdentity` in
  `CollectionProcessingIntegrationTests.swift`.
- Surface: production processor, real TMDb decoding, fake HTTP transport, isolated persistence and folder fixtures.

### R120-A5 — Competing direct and alias evidence remains ambiguous

**Given** a complete search has a direct title candidate and another candidate with the same verified alternative title,
**When** the processor completes assessment,
**Then** the persisted collection result is `Several matches` with no selected movie ID.

- Requirement: preserve ambiguity and never choose by provider order or artwork availability.
- Automated test: `competingInternationalEvidencePersistsSeveralMatches` in
  `CollectionProcessingIntegrationTests.swift`.
- Surface: production processor, real TMDb decoding, fake HTTP transport, isolated persistence and folder fixtures.

### R120-A6 — Alias request limit is observable in saved outcomes

**Given** a complete search returns five eligible candidates,
**When** the processor requests alias evidence,
**Then** it makes five or fewer alias requests;
**Given** the search returns six eligible candidates,
**When** the processor assesses the folder,
**Then** it makes no alias requests and persists manual matching as required.

- Requirement: bounded provider request budget and safe over-limit behavior.
- Automated test: `candidateBoundaryPersistsBoundedMatchingResult` in
  `CollectionProcessingIntegrationTests.swift` (two parameterized cases).
- Surface: production processor, real TMDb client, fake HTTP transport, isolated persistence and folder fixtures.

### R120-A7 — Language and credential context do not reuse alias cache entries

**Given** alias evidence has been cached for one language and credential revision,
**When** the processor assesses the same candidate under a different language and then a different credential revision,
**Then** each changed context requests fresh provider evidence while preserving the same supported movie identity.

- Requirement: metadata cache keys include language and credential context.
- Automated test: `languageAndCredentialChangesDoNotReuseCachedAliasEvidence` in
  `CollectionProcessingIntegrationTests.swift`.
- Surface: production matching/cache path, real TMDb client, fake HTTP transport and isolated persistence.

## Scope notes

- Migration compatibility and confirmed-ID preservation remain covered by the issue's validation tests; acceptance
  scenarios here focus on user-visible settings and the changed matching/cache behavior.
- These tests do not register or launch the Finder extension. Host-app settings and processor integration are tested
  without touching real user collections, credentials, or poster icons. A3 seeds a saved unresolved result through the
  same isolated persistence namespaces the app reads; it then exercises the actual host-app results and action windows.
